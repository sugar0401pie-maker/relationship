# 쏠 마을 관계성 테스트 — 방향별 유형 관계 설명 작성 규칙 (441개)

## 무엇을 쓰나
결과를 보는 사람(=나, 유형 A)이 연인({애칭}, 유형 B)을 바라보는 방향의 관계 설명. "수달→해달"과 "해달→수달"은 다른 글이다(시점·역할·한 걸음이 다름). 같은 유형끼리(수달→수달)는 하나만 쓴다.
각 task(JSON)에 나·상대의 유형 데이터(강점·약점·제안), 캐릭터 설정(사는 곳, 생활, 대표적인 변화, 숨은 바람), 고리 키와 '나의 고리 역할'(A/B), 고리 문장(loop_flow: 계기/A/B/끝/맞물림/다리), 공통점·차이점이 들어 있다. **이 재료와 어긋나는 내용을 지어내지 않는다.**

## 출력 형식 (task마다 객체 1개, 순서 유지, JSON 배열)
{
 "id": "수달→해달",

 "흐름": "3~4문장. 고리 문장의 계기→(나의 역할에 맞는) 나의 첫 움직임→{애칭}의 반응→끝을 이 두 유형에 맞게 구체화.",

 "이야기_한줄": "인스타툰 표지용 한 줄(25자 안팎)."
}

## 말투
- 무료_설명·흐름·서로에게_주는_것·엇갈리는_순간·내가_해볼_한_걸음: **합쇼체(~습니다/~입니다, 제안은 ~해 보세요)**. 해요체(~해요) 금지. 질문은 "~할까요?" 가능.
- 쏠_마을_이야기: '~했다' 과거 서술체. 대사는 따옴표 안 반말 구어체.
- 부탁해_볼_말: 따옴표 안 반말 구어체 한 문장.
- 나 = "당신", 상대 = "{애칭}". 조사는 자리표시자로: {애칭|은} {애칭|이} {애칭|을} {애칭|과} {애칭|으로}, 받침 무관은 그대로 {애칭}에게 / {애칭}의 / {애칭}도. 쏠_마을_이야기와 이야기_한줄에는 {애칭}을 쓰지 않고 캐릭터 이름만 쓴다.
- 문장은 짧고 구체적으로. 한 문장 60자 안팎. 이모지 금지. "여러분" 금지.

## 반드시 지킬 것
- 상대를 판정하지 않는다: "회피형", "불안형", "~한 사람입니다(단정)", "~패턴입니다", "문제입니다" 금지. 상대의 약점은 '~할 때가 있을 수 있습니다'처럼 흐름으로.
- 헤어지라/참으라/견디라는 조언 금지. 결론은 늘 작은 한 걸음.
- 통제·감시(위치 공유 요구, 휴대폰 확인 등)를 애정이나 해법으로 쓰지 않는다.
- 없는 통계·연구 수치를 만들지 않는다. 학자 이름 쓰지 않는다.
- 같은 유형끼리(A=B): 공통점이 크게 겹치는 사이로 쓰고, 둘 다 같은 자리에서 막히는 장면을 쓴다. 이야기는 두 캐릭터를 구분해 "윗강 수달과 아랫강 수달", "선착장의 펭귄과 장터의 펭귄"처럼 부른다.
- 나의 고리 역할이 A면 고리 문장의 A 자리가 나, B면 B 자리가 나. 두 방식이 같은 고리(다가가기×다가가기 등)면 둘 다 같은 움직임을 한다.
- 바다의 노인(히든): 쏠 마을의 유일한 사람, 늙은 어부. 썰물 때 길이 열리는 먼 섬에 살며 가끔 마을에 들른다(고정된 짝 없음 → 이야기에서는 '가끔 만나는 사이'로). 말을 아끼고 서운함·힘듦·그리움을 혼자 견딘다(말하기×거리두기 극단 + 기대기 낮음). 실존 작가 이름·소설 문장 금지. 바다의 노인이 '나'인 경우 그의 속마음으로 쓴다.
- 캐릭터 외형 규칙: 가오리·해파리·불가사리·조개 등은 손을 추가하지 않는다(몸·지느러미·촉수·껍데기로 표현).
- 공통점·차이점 문장을 그대로 복사하지 말고 재료로 쓴다. 441개가 서로 비슷한 문장 틀로 반복되지 않게, 특히 엇갈리는_순간과 쏠_마을_이야기는 쌍마다 다른 구체 장면을 쓴다.
