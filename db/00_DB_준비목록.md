# 강에 사는 나, 바다에 사는 너 — 쏠 마을 관계 테스트 — DB 준비 목록 v0.1 (2026-10-07)

DB로 준비할 것은 두 종류입니다.
- **서비스 DB**: 사용자가 테스트하면서 생기는 데이터(응답·결과·결제·리포트·공유). Supabase 테이블.
- **콘텐츠 DB**: 화면과 리포트에 들어가는 문장·실천 연결. 지금은 JSON 한 파일인데, 검수·수정을 위해 엑셀 문장 DB로 관리.

## 급한 순서

## 테이블 한눈에 보기

```
auth.users ─┬─ rel_sessions (1회 테스트) ─┬─ rel_answers (문항별 응답 39줄)
            │                            ├─ rel_results (채점 결과, 무료 섹션 렌더)
            │                            ├─ rel_reports (결제 후 AI 리포트) ── orders (기존)
            │                            ├─ rel_share_links (공유 카드) ──→ 새 rel_sessions.invited_by
            │                            └─ rel_events (퍼널)
            └─ rel_user_profile (최신 관계 유형 → 쏘웰라)
```

## 결정·확인이 필요한 것

| 항목 | 내용 | 누가 |
|---|---|---|
| 기존 테이블 이름 | 디저트 테스트의 결제(orders)·리포트·AI 채팅권 테이블 이름과 구조. 리포트 테이블을 공용으로 쓸지(test_type 칸 추가) 따로 둘지 | 개발 |
| 상대에 대한 응답 보관 | **결정(2026-10-21): 비로그인 세션은 응답·결과를 30일 보관 후 자동 삭제.** 첫 화면 안내(onboarding_bullets 3번)도 같은 내용으로 수정. 로그인 저장 시 동의 문구와 상대 정보 보관 범위는 법률 검토 | 법률 검토 |
| 안전 문항 저장 | 원응답은 저장하지 않고 결과의 safety_flag만 남기는 안. 계정 위기 이력과 연동할지(D19 실천 제외에 쓰임) | CSO·상담사·법률 |
| 실천 연결 고도화 | 1차 후보는 채움. 실천 DB 승인 상태·전체 본문 확인 후 확정, 공백 7개는 실천 신규 작성 검토 | CSO·상담사 |
| 문장 DB 원본 전환 시점 | 상담사 검수가 시작되면 엑셀을 원본으로, JSON은 반영 결과로만 취급 | CSO |

## 쓰는 방법

1. **스키마**: `01_schema_draft.sql`을 Supabase SQL 편집기에서 실행하기 전에, 맨 위 주석의 가정(orders 등 기존 테이블 이름)을 실제 이름으로 바꾸고 RLS 정책을 붙입니다.
2. **문장 DB**: 상담사가 `03_문장DB.xlsx`의 크림색 칸(상태·수정안·메모)을 채움 → `python import_sentence_db.py import 03_문장DB.xlsx ../02_데이터/relationship_test_data.json --confirmed-only`로 확정분만 반영. 자리표시자가 깨졌거나 금지 표현이 있으면 반영하지 않고 목록으로 알려줍니다.
3. **가짜 문장**: 결제 전 블러 구간은 `02_placeholder_sentences.json`에서 세션 id를 시드로 뽑아 채웁니다.
