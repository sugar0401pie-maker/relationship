## 1. 분류 체계

### 1.1 5개 관계 역량 (= 계열)

각 역량은 **속(마음)** 과 **겉(행동)** 두 하위요인으로 나뉩니다. 상대의 속마음은 볼 수 없으므로 2부는 겉만 묻습니다.

| 역량 | 계열 | 캐릭터 | 묻는 것 | 이론 근거 |
|---|---|---|---|---|
| 기대기 (친밀감) | 물가 털복숭이 | 수달·해달·물범·비버 | 힘든 날 마음을 열고 기대고 도움을 청하는가 | 성인 애착 회피 차원(Hazan & Shaver; Brennan·Clark·Shaver), EFT 효과적 의존, 스키마 정서적 결핍 |
| 믿기 (안정감) | 물새 | 원앙·펭귄·왜가리·백조 | 연락 공백·거리감 앞에서 상대 마음을 믿고 편안한가 | 애착 불안 차원, 신뢰 이론(Rempel), 스키마 버림받음·불신 |
| 선 지키기 (경계) | 껍데기와 가시 | 복어·소라게·거북·조개 | 원치 않는 부탁을 거절하고 내 시간·취향을 지키는가 | 자기분화(Bowen), 경계 이론(Cloud & Townsend), 스키마 복종·자기희생, DBT 자기존중 |
| 말하기 (표현) | 소리 | 물개·돌고래·혹등고래·개구리 | 서운함·바람을 겉감정이 아니라 속마음으로 말하는가 | 자기개방(Altman & Taylor), EFT 겉감정·속감정, DBT 표현·경청, IPT 소통 되짚기 |
| 회복하기 (갈등) | 갯벌과 바닷속 | 문어·해파리·가오리·불가사리 | 다툰 뒤 마음을 가라앉히고 다시 이어지는가 | 회복 시도(Gottman), EFT 끊김 뒤 다시 잇기, DBT 감정 조절 |

계열별 결과 화면 문구·상징·흔들릴 때 모습은 데이터 `families`.

**역량 연결**(관계 문장의 "관계 구분"에 사용): 기대기–믿기(애착의 두 차원), 선 지키기–말하기(자기주장), 말하기–회복하기(속감정과 다시 잇기).

### 1.2 4가지 방식

| 방식 | 결 | 근거 |
|---|---|---|
| 다가가기 | 적극성: 확인하고 맞서고 바로 움직임 | 스키마 '맞섬', EFT 다가가는 쪽 |
| 맞춰주기 | 배려: 따르고 삼키고 양보 | 스키마 '따름', IPT 삼킴 |
| 거리두기 | 자기보호: 피하고 물러나 혼자 정리 | 스키마 '피함', EFT 물러나는 쪽 |
| 조율하기 | 신중함: 멈추고 정리한 뒤 고름 (느리고 오래 걸림) | EFT 세 번째 길, DBT 둘이 만난 마음 |

**절대 원칙**: 어떤 방식도 더 낫지 않습니다. 모든 방식은 "한때 나를 지켜준 방법"으로 설명하고, 조율하기에도 약점을 똑같이 씁니다.

### 1.3 21유형

유형 = **가장 에너지가 필요한 역량(가장 낮은 역량) × 그 역량에서 주로 쓰는 방식**.
유형별 이런 모습·대비 한 줄·강점 5·약점 5·제안 3은 데이터 `types`.

| 역량 \ 방식 | 다가가기 | 맞춰주기 | 거리두기 | 조율하기 |
|---|---|---|---|---|
| 기대기 | 수달 | 해달 | 물범 | 비버 |
| 믿기 | 원앙 | 펭귄 | 왜가리 | 백조 |
| 선 지키기 | 복어 | 소라게 | 거북 | 조개 |
| 말하기 | 물개 | 돌고래 | 혹등고래 | 개구리 |
| 회복하기 | 문어 | 해파리 | 가오리 | 불가사리 |

**히든: 바다의 노인** — 말하기 × 거리두기가 아주 강할 때. 소설 『노인과 바다』의 분위기만 빌린 오리지널 캐릭터(헤밍웨이 이름·얼굴·원문 인용 사용 금지). 계산상으로는 말하기 × 거리두기와 같이 취급.

## 3. 문항 (원문은 데이터 파일 — 문구·점수·순서 임의 변경 금지)

### 3.1 공통
- 모든 문항은 **장면 + 4지선다**. 보기 점수는 **4·3·2·1**(높을수록 그 역량이 편안함). 화면에 점수 비노출.
- 보기 화면 순서는 데이터의 `display_order`로 **고정**(사용자마다 랜덤 아님). 점수 순서가 드러나지 않게 미리 섞어 둔 것.
- 문항 텍스트의 `{애칭}은/이/을/과`는 `normalizeItemText()` → `render()`로 조사 자동 처리.
- 결혼·동거 선택 시 `결혼`(장면) / `결혼_보기_override`(보기 index별 문구)가 있으면 대체.

### 3.2 1부 — 나 (역량 20 + 방식 4)

**역량 장면 20개** (`part1_competency`, 노출 순서 `part1_order`)
- 역량마다 4문항: **속1·속2**("그때 내 마음은?"), **겉1·겉2**("그때 나는?").
- **문항마다 상황이 다름.** 속n과 겉n은 **보기 구조가 같고**(마음 버전 ↔ 행동 버전, 예: "연락하고 싶다" ↔ "연락한다") 상황만 다름.
- 비교 구조:
  - 속1 ↔ 겉1, 속2 ↔ 겉2 → **마음과 행동의 간격**
  - 속1 ↔ 속2, 겉1 ↔ 겉2 → **응답 일관성**
- 노출 순서는 같은 역량이 연달아 나오지 않게, 짝(속n·겉n)이 떨어지게 배치됨.

**방식 장면 4개** (`mode_scenes` 중 `부 == "1부"` 이고 `역량 == 확정 역량`인 4개, M1-역량-1→4 순)
- 보기 4개가 각각 4가지 방식(그 계열 캐릭터 4마리의 행동)에 대응. 점수가 아니라 **방식 투표**.
- 역량별 4개씩 총 20개를 만들어 두고, 사용자는 자기 확정 역량의 4개만 봄 (디저트 테스트 2부가 확정 영역 고민을 떠올리게 한 것과 같은 원리).

### 3.3 2부 — 내 눈에 비친 {애칭} (역량 10 + 방식 4)
- 상대의 **행동만** 묻고 마음은 묻지 않음. 장면 끝은 "{애칭}은 보통", "가장 자주 보았던 모습"을 고르게 함.
- 모든 문항에 **"잘 모르겠어요"** 보기 추가(점수 계산 제외).
- 역량 장면 10개(`part2_competency`): 역량마다 비슷한 장면 2개(A·B) → 일관성 확인. 1부와 다른 장면·다른 문장.
- 방식 장면 4개: `mode_scenes` 중 `부 == "2부"`, 그 사람 확정 역량의 4개.

### 3.4 안전 안내 (문항 없음, 2026-10-22 변경)
안전 확인 문항은 삭제했습니다. 폭력·간섭을 겪는 관계라면 관계성(궁합)을 보는 것 자체가 맞지 않으므로, 묻는 대신 **시작 화면에 안내를 고정 표시**합니다(`ui_copy.safety_notice_start` + `safety_contacts`). 같은 문구를 결과 하단 고지문(`disclaimer`)에도 연락처와 함께 넣습니다.
통제·감시 행동(위치 공유 요구, 휴대폰 확인 등)은 일반 장면 보기에 넣지 않습니다.

## 4. 채점 (코드: `03_코드/scoring.js`, 테스트: `test_scoring.mjs` — 19개 통과)

| 단계 | 규칙 |
|---|---|
| 1부 역량 점수 | 역량 = 속1·속2·겉1·겉2 평균 (1.0~4.0). 속 = 속1·속2 평균, 겉 = 겉1·겉2 평균 |
| 내 주 고민 역량 | 가장 낮은 역량. 동점 → **겉 점수가 더 낮은 역량** → 그래도 같으면 확인 화면(동점 역량만). **5개 모두 3.5 이상** → 확인 화면(5개 중 선택) |
| 가까운 이웃 | 확정 역량과 다음으로 낮은 역량 차이 ≤ 0.5 → "○○의 결도 있습니다" |
| 내 방식 | 확정 역량 방식 장면 4개 다수결. 2:2 / 1:1:1:1 → 확인 화면(동점 방식만) |
| 내 유형 | 확정 역량 × 방식. **히든**: 말하기 × 거리두기 + 거리두기 3표 이상 + 기대기 역량 ≤ 2.0 → 바다의 노인 |
| 속·겉 간격 | (속1−겉1), (속2−겉2)가 같은 방향이고 평균 |차이| ≥ 1.5 → "내 마음" 문장 후보. 여러 개면 확정 역량 → 간격 큰 순 → 고정 순서 |
| 일관성 | 속1↔속2 또는 겉1↔겉2 차이 3(1점 vs 4점) → 해당 역량 "상황에 따라 다릅니다". 3개 역량 이상 → 전체 안내 |
| 그 사람 역량 | 장면 A·B 평균("잘 모르겠어요" 제외). 둘 다 모름 → "아직 잘 보이지 않는 부분"(계산 제외). A·B 차이 3 → 상황에 따라. 판단 가능 역량 3개 미만 → 2부 유형 대신 안내 |
| 그 사람 주 고민 역량 | 가장 낮은 역량. 동점 → 바로 확인 화면 "{애칭}에게 더 가까운 쪽은?" |
| 그 사람 방식 | 방식 장면 4개 다수결("잘 모르겠어요" 제외). 동점 또는 유효 2개 미만 → 확인 화면 |
| 그 사람 유형 | 나와 같은 규칙(히든 포함). 화면 제목은 항상 "내 눈에 비친 {애칭}" |
| 우리 고리 | 내 방식 × 그 사람 방식 → 10가지 (`loopKey()`, 순서 무관). 문구 `loop_flow` |
| 가장 엇갈리는 지점 | 역량별 |내 겉 − 그 사람 점수| 최대. 1.5 이상만 노출, 없으면 "크게 엇갈리는 곳이 없습니다" |
| 먼저 건네기 저울 | (내 말하기 겉 + 내 회복하기 겉)/2 − (그 사람 말하기 + 회복하기)/2. |값| < 0.6 균형 |
| 상리공생 배지 | 저울 균형 + 두 사람의 모든 겉 점수 ≥ 3.0 → "서로 주고받는 사이" |
| 안전 | 문항 없음. 시작 화면 안전 안내 + 결과 고지문(연락처 포함). `scoring.js`의 `safetyFlag`는 쓰지 않음 |

**원칙**: 무작위 선택 금지(동점은 전부 규칙 또는 확인 화면). 1부는 필수 응답, 2부는 "잘 모르겠어요" 허용.
**기준값**(3.5, 0.5, 1.5, 2.0, 0.6 등)은 `TH` 상수로 모아 둠 → 파일럿 후 조정.

| **무료 — 카드** | 내 유형 카드(유형명·계열 태그·계열 문구·이런 모습·대비 한 줄·가까운 이웃) / 내 눈에 비친 {애칭} 카드 / 두 사람 레이더 겹쳐 그리기 / 우리 고리 이름 |
| **무료 — 쏠 마을 이야기 카드** | 우리 고리 카드 아래. 제목 `pair_relations[나→애칭].이야기_한줄` + 본문 `쏠_마을_이야기`(4~6문장, 두 캐릭터가 쏠 마을에서 엇갈렸다가 작은 한 걸음을 내딛는 이야기) + 두 캐릭터 그림 |
| **무료 — 리포트 1~3** | 1. 우리 사이를 딱 두 줄로 표현한다면 (관계 문장 공통점+차이점 → 바로 아래 방향별 소개 문단 `무료_설명`) / 2. 당신은 이런 사람입니다 (+관련 이론) / 3. 당신이 보는 {애칭}은 이럴 거예요 — 모두 AI 없이 서버가 조합 |
| **미리보기** | 4. 우리 관계는 보통 이렇게 흘러갑니다 — 앞 2줄만 공개 ("{고리}입니다. {계기} 그러면 {나의 첫 움직임}") |
| **블러 구간** | 4번 본문, 5. 당신이 주로 서운함을 느끼는 순간은... / 6. {애칭}은 주로 이럴 때 서운함을 느껴요 / 7. 관계 개선 방향 / 8. 오늘 해볼 수 있는 것 — 제목은 선명, 본문은 blur(6px) + 투명도 그라데이션 |
| **결제 카드** | 블러 위에 겹침. 제목·포함 내용·2,900원·"2,900원 결제하고 이어서 읽기" |
| **하단 고정 바** | 결제 카드를 지나면 고정: "전체 리포트 + 1주일 AI 채팅권 · 2,900원 · 이어서 읽기" |
| **결제 후** | 새 페이지로 가지 않고 같은 스크롤 위치에서 블러 해제. AI가 4번 본문~8번을 그 자리에서 "만드는 중" 후 채움 |
| **공유 카드** | 무료 (바이럴 통로). "{이름}의 시선으로 본 우리" + 고리 + 리포트 1번 두 줄 + 쏠 마을 이야기 한 줄 + "당신이 보는 우리는?" 버튼. 결제 시 "내 마음" 문장 추가. **상대 점수·약점은 넣지 않음** |
| **고지문** | 결과 하단 고정 (`ui_copy.disclaimer`) |

**캐릭터 표시**: 우리 고리 카드에는 **두 사람의 실제 캐릭터**를 그림. `loops`의 대표 짝(20 캐릭터가 한 번씩)은 고리 소개·공유 이미지 기본값용.

**보안**: 결제 전에는 유료 본문을 DOM에 넣지 않음(CSS 블러는 개발자 도구로 풀림). 블러 구간에는 길이만 비슷한 가짜 문장을 서버가 생성.
**비용**: AI 리포트는 결제 후 생성. 미리보기는 AI 없이 이미 계산된 문구로만 구성.
**금지**: 가짜 카운트다운, "지금만 할인" 같은 압박 문구. 가격은 버튼 전에 분명히 표시.
**측정**: 결과 진입 → 미리보기 지점 도달 → 결제 카드 노출 → 버튼 클릭 → 결제 완료 이벤트. 끊는 위치 A/B(고리 2단계 vs 엇갈림 첫 문장).

## 6. 결과 문구 (데이터 파일)

| 키 | 내용 | 렌더 변수 |
|---|---|---|
| `types[]` | 이런 모습, 대비 한 줄, 강점 5, 약점 5, 제안 3 | {애칭} |
| `families[]` | 계열 결과 문구, 상징, 묻는 것, 흔들릴 때, 이론, 연결 | {애칭} |
| `pairs[]` | 231쌍 공통점·차이점. **{A}/{B} 템플릿**(유형 이름 없음) — `pairs_render` 규칙대로 내 쪽을 {이름}, 상대를 {애칭}으로 바꿔 렌더 | {A},{B} → {이름},{애칭} |
| `pair_relations{}` | **방향별 관계 441개** ('내 유형→내 눈에 비친 {애칭} 유형'). 필드 8개: 무료_설명(나는 {이름}, 상대는 {애칭})·쏠_마을_이야기·이야기_한줄(무료) / 흐름·서로에게_주는_것·엇갈리는_순간·내가_해볼_한_걸음·부탁해_볼_말(유료 AI 재료, 결제 전 전송 금지). 쓰는 자리는 `pair_relations_usage` | {애칭} |
| `loop_flow{}` | 10고리 × 계기·A·B·끝맺음·잘 맞물리는 순간·다리 놓기(+거리두기×거리두기 안내) | {A},{B} = 앞쪽 방식 사람, 뒤쪽 방식 사람 |
| `mismatch{}` | 역량 × (me_higher/partner_higher) + none | {애칭} |
| `balance{}` | balanced / me / partner / badge | {애칭} |
| `inner_outer{}` | 역량 × (inner_higher/outer_higher) + default — 공유 카드 "내 마음" 문장 | {애칭} |
| `ui_copy{}` | 결과 문장, 히든 공개, 확인 화면, 안내문, 안전, 페이월, 공유, 고지문 | {이름},{애칭},{유형},{역량} 등 |

템플릿 문법: `{키}` 값, `{키|은}` 값 + 받침에 맞는 조사. `josa.js`의 `render()` 사용. **조사 하드코딩·"은(는)" 병기 금지.**

## 8. 반드시 지킬 것

1. 문항·보기·점수·노출 순서를 임의로 다듬지 말 것 (검수 거친 문구).
2. 무작위 선택 금지. 동점은 규칙 → 확인 화면.
3. 조사는 `josa.js`로만 처리.
4. 2부·공유·리포트 어디서도 상대를 **판정하지 않음**: "회피형/불안형", "○○ 패턴입니다", 관계를 이어가라/끝내라 권유 금지. 2부 결과는 항상 "내 눈에 비친".
5. 공유 카드에 상대 점수·약점 노출 금지.
6. 시작 화면에 안전 안내(`safety_notice_start` + 연락처)를 반드시 표시하고, 결과 하단 고지문에도 넣음.
7. 유료 본문을 결제 전 클라이언트로 보내지 말 것.
8. API 키는 서버에서만.
9. 바다의 노인: 헤밍웨이 이름·얼굴·소설 원문 사용 금지.
